# Source Brief

## Core Idea
The video argues that a short high-capability model window should be spent on projects where autonomy, planning, and complex execution actually matter, not on casual one-off prompts.

## Process Insight
The strongest pattern is not "ask the best model to build everything from scratch." The workflow is: use a cheaper or familiar model for research, planning, PRD drafting, and success criteria; then hand the well-scoped long-running job to the stronger model.

## Five Source-Derived Use Cases
1. Clone useful software you already pay for, especially when a local/private version would be better, such as the Whisper Flow-style dictation clone in the demo.
2. Audit your Claude Code usage across previous sessions to find missing skills, automations, fixes, or habits that should stay unchanged.
3. Build a personal or team agentic OS: a visual wrapper over Claude Code with reports, skills, automations, metrics, and task launchers.
4. Point the model at code review and debugging for complex codebases; the demo produced 45 raw findings from four reviewers and 24 deduplicated issues.
5. Use a clear PRD for long-horizon custom software; the cited Three.js browser game shows why requirements and constraints matter before autonomous execution.

## Audience Angles
- Services: a practical framework for deciding which AI automation projects deserve the most capable model.
- Course: beginner-friendly lesson on turning vague AI interest into concrete projects: clone, audit, systemize, review, and build.
- Operator: use high-capability models where the bottleneck is planning depth and long execution, not simple text generation.
