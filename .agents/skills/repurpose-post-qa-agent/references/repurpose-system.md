# Repurpose System

## Objective

Turn one verified source into original Stanley-native content for LinkedIn,
Instagram, X, and Facebook while preserving the source's useful structure,
claim, proof, examples, and CTA.

## Canonical Path

Use only:

- `.agents/skills/repurpose-youtube-video-v3/SKILL.md`
- `workflows/repurpose-social-full-package-dumb-model-sop.md`

Do not combine competing repurpose SOPs.

## Source Gate

For every LinkedIn or social post, analyze the caption/body and attached image,
GIF, screenshot, or carousel; state what each contributes; reject unrelated
captures; and record verified claims and missing evidence. Do not draft when
essential evidence is missing.

## Content Path

The default narrative path is:

1. Hook: bold specific claim, tension, or number.
2. Stakes: why the problem matters now.
3. Value: one useful idea per slide.
4. Receipts: proof, result, screenshot, example, or checkable number.
5. CTA: one clear next action.

This is a story path, not a fixed visual template. Slide count may expand when
the source requires one slide per tool, step, role, case, or proof.

## Department-Task Promise

Before drafting, complete this chain:

```text
Department -> repeated task -> current friction -> available input -> mechanism
-> usable output -> faster/easier outcome -> proof or guardrail
```

The public hook should lead with the task, cost, delay, output, or operational
promise. Do not make a model release or tool name the main idea unless the
departmental use case is immediately obvious.

Strong pattern:

```text
[One familiar input] -> [clear workflow] -> [finished work product or decision]
```

Examples include a product URL to a ranked creative test plan, an ad export to
a prioritized audit, customer reviews to a language bank, or a winning ad to a
set of shoot-ready variations. Use only source-supported numbers and speed
claims.

## Instagram Rules

- Canvas: 1080x1440, 3:4.
- Cover: gigantic heavy title, maximum three lines and usually six words or
  fewer; concise 3-4 line summary when context is needed; numeric proof when
  available.
- Teaching slides: big type, short lines, one main idea, meaningful diagrams,
  and dense but scannable value.
- Receipts: real proof only.
- CTA: one keyword or one action, never two asks.
- Caption: keyword CTA must be last.

Each slide should teach when encountered alone, but public copy must never say
"standalone post," "source," "caption," "repurpose," or other internal
production language.

## Dynamic Visual Logic

- Comparison -> split comparison or matrix.
- Sequence -> process flow or timeline.
- Decision -> tree, route map, or effort dial.
- Cost -> cost ladder, leak meter, or ratio chart.
- System -> architecture map or workflow loop.
- Tool list -> one tool per slide with function and process.
- Proof -> receipt, dashboard, screenshot, or before/after result.
- Anatomy -> labeled breakdown.
- Audit -> scanner, checklist, or scorecard.
- Hierarchy -> pyramid or layered stack.

Do not reuse the same card grid, bottom panel, prompt box, or diagram shell
across neighboring slides or unrelated projects.

## Caption Rules

Keep the caption about 70% similar to the reference caption's structure and
core content while paraphrasing into Stanley's voice:

1. Natural scroll-stopping hook.
2. Why it matters now.
3. Useful mechanism, framework, or body.
4. Proof, number, example, or checkable detail.
5. One final CTA.

The keyword CTA is the last ask, not the opening line.

The caption body must make the operational promise tangible by naming the
input, process, output, and where human review is still required. Generic
benefits such as `save time`, `work smarter`, or `crush marketing` are not
enough without the concrete task they apply to.

## Completion Rule

Rendering is not completion. A package is complete only after this QA agent
reviews the final media, repairs are rerendered, and the final report passes.
