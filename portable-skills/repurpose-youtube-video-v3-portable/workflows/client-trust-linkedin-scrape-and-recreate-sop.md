# Workflow: Client Trust LinkedIn Scrape And Recreate SOP

## Objective

Turn high-performing LinkedIn reference posts into original Stanley content that
builds trust for AI automation services.

The goal is not to copy creators. The goal is to learn the content mechanics:
hook, pain point, workflow, proof, visual pattern, and CTA.

## Use This When

The user provides:

- LinkedIn posts.
- Screenshots of LinkedIn posts.
- Creators to study.
- A request for AI automation trust-building content.
- A request to recreate content that makes clients want to work with Stanley.

## Required Output

For analysis-only reference batches, create a local package or reference file containing:

- Source links.
- Public accessibility status.
- Creator/topic summary.
- Hook pattern.
- Trust mechanism.
- Visual pattern.
- Stanley recreation angle.
- Original draft ideas.
- Editable visual directions or generated editable visuals.
- Notes about blocked or missing source material.

For any request phrased as "repurpose this post", "recreate this post", "turn
this into content", or similar, this SOP is only the first half of the job. The
final deliverable must continue into `repurpose-youtube-video-execution-sop.md`
and produce the full social package:

- `source/transcript.txt` or source capture notes with confidence.
- `source/source-brief.md`.
- All required platform text files.
- All required visual prompt files.
- Actual generated PNG files in `drafts/<Platform>/images/`.
- A LinkedIn GIF when the idea is a process, framework, sequence, or educational walkthrough.
- `preview/preview.md`.
- `preview/image-qa.md`.
- A valid `manifest.json` with generated image and animation counts.

Do not treat `source-analysis.md`, a LinkedIn text draft, an editable SVG, or a
few flat PNG exports as complete repurposing output.

## Hard Rules

- Do not copy posts verbatim.
- Do not bypass login, paywall, or site access restrictions.
- Use public text only unless the user provides screenshots or pasted source.
- Do not invent proof.
- Do not claim Stanley did work shown by another creator.
- Save source summaries, not full copied post archives.
- Recreate the strategy, not the wording.
- Social content is not complete with text only. It must include visuals.
- When Penpot is available, editable SVGs must be imported there automatically.

## Source Intake Steps

1. Open every link.
2. Record whether the post is publicly accessible.
3. Extract:
   - creator name
   - post title/topic
   - date or relative age
   - reaction/comment count if visible
   - main hook
   - automation mechanism
   - proof point
   - CTA
   - visual attachment type
4. If the page is blocked, ask the user for screenshots or pasted text.
5. Save findings under `AIS-OS/references/` or the relevant content project.

## Analysis Steps

For each post, classify it into one of these archetypes:

- One-line fix.
- Rebuilt system teardown.
- Full stack inventory.
- Contrarian CEO/client warning.
- Natural-language automation demo.
- Client expectation reality check.
- Wow-moment case study.

Then write:

```text
What this post teaches:
...

Why it builds trust:
...

How Stanley should recreate the pattern:
...
```

## Stanley Recreation Formula

Use this structure:

```text
Hook:
Name a costly manual bottleneck, mistake, or surprising automation.

Context:
Describe the client situation in plain English.

Mechanism:
Show how the AI workflow works.

Proof:
Mention a real artifact, step, time saved, system output, or demo.

Lesson:
Explain what the client should now understand.

CTA:
Invite a DM, comment, or workflow audit.
```

## Visual Workflow

Create visuals that feel like practical business artifacts:

- workflow map
- before/after process
- stack diagram
- teardown checklist
- command-to-output diagram
- client reality check card
- proof board

For social output, visuals are mandatory. At minimum, create:

- one LinkedIn feed visual
- one carousel/slide direction set when the idea needs multiple steps
- one reusable editable source file, preferably SVG

If the user asked for a full repurpose package, the minimum above is not enough.
Use the full generated-media contract in
`workflows/repurpose-youtube-video-execution-sop.md`, including platform image
folders, image QA, and manifest counts.

If Penpot is running:

1. Generate editable SVGs.
2. Auto-import them into Penpot.
3. Save the Penpot workspace URL in the preview/manifest.

Do not stop at flat PNGs when the user wants manual editing.

## Done Criteria

Before saying the work is complete, check:

- Every source link is recorded.
- Blocked sources are marked honestly.
- No full post was copied as the final artifact.
- Every reference has a Stanley recreation angle.
- The final guidance is specific to AI automation services.
- Editable visual assets are generated.
- Penpot import was attempted when Penpot is running.
- The package clearly separates source inspiration from original Stanley drafts.
- If the user asked to repurpose/recreate into content, the full
  `repurpose-youtube-video-execution-sop.md` checklist also passes.
